# 상담사 근무표의 활동 구간 재구성과 휴가 반영

## 개요

| 항목 | 내용 |
| --- | --- |
| 프로젝트 | 콜센터 상담사 근무관리(WFM) 시스템 구축 |
| 기간 | 2025.11 ~ 2026.10 |
| 역할 | 개발자 6명 중 스케줄 관리(이행률 포함)/통계(실시간 포함) 영역 담당, 화면, 서버 로직, SQL 개발 |
| 기술 | Java, Spring Framework(전자정부프레임워크), MyBatis, Oracle, Nexacro N24 |

## 업무 상황

상담사 근무표는 근무조 편성으로 생성된 기본 근무 구간(예: 09:00~18:00 상담) 위에 점심, 회의 같은 활동이 겹쳐 들어오는 구조입니다. 관리자는 30분 단위 시간표 화면에서 활동을 드래그앤드롭으로 넣거나 시간을 바꿉니다.

여기에 인사 시스템에서 연계된 휴가가 더해집니다. 반차, 반반차, 종일휴가가 있고, 하루에 휴가가 여러 건 들어오기도 합니다.

## 문제

하나의 입력이 여러 기존 활동에 동시에 영향을 줍니다. 예를 들어 상담, 점심, 상담으로 나뉜 근무표에 11:30~12:30 회의가 들어오면, 앞쪽 상담과 점심을 모두 잘라야 합니다. 이때 겹치지 않는 시간은 원래 활동으로 정확히 남아야 하고, 빈틈이나 중복 구간이 생기면 안 됩니다.

휴가는 규칙이 더 있었습니다.

- 철야조는 소정근로시간이 주간과 달라 반차 시간을 고정값으로 쓸 수 없었습니다.
- 오전반차와 오후반차가 따로 들어오면 종일휴가로 봐야 하는데, 두 휴가 사이에 점심이 끼어 시간이 이어지지 않았습니다.
- 오전반차와 오후 반반차처럼, 두 휴가 사이에 실제 근무가 남는 경우도 있었습니다.

## 해결

**구간 재구성.** 신규 활동과 겹치는 기존 활동마다, 신규 활동보다 앞에 남는 시간과 뒤에 남는 시간을 원래 활동으로 남기고 겹친 부분은 신규 활동으로 바꾸도록 서버에서 처리했습니다.

| 시작 | 종료 | 활동 |
| --- | --- | --- |
| 09:00 | 11:30 | 상담 |
| 11:30 | 12:30 | 회의 |
| 12:30 | 13:00 | 점심 |
| 13:00 | 18:00 | 상담 |

근무활동 상세 데이터는 시작시각 기준으로 한 건만 존재하는 구조였습니다. 그래서 시작시각이 같은 활동을 바꿀 때는 기존 행을 삭제하고 새 행을 삽입했고, 활동 시간을 줄이면 남은 시간을 원래 활동으로 다시 등록했습니다. 여러 행의 삭제/삽입은 하나의 처리 단위로 묶어 중간에 오류가 나면 전체 롤백되도록 했습니다.

**휴가 반영.** 철야조는 반차 시간을 소정근로시간의 절반으로 계산하되, 오전반차는 30분 단위 내림, 오후반차는 올림으로 맞췄습니다(예: 10.5시간 철야조는 오전 5시간, 오후 5.5시간). 종일 여부는 시간이 이어지는지가 아니라 그날 휴가 시간의 합계로 판정했습니다. 종일휴가는 근무 상세를 모두 지우던 기존 방식에서, 근무시간만큼 휴가 구간을 등록하는 방식으로 바꿨습니다.

## 결과

- 신규 활동이 여러 활동에 걸쳐도 잔여 시간을 보존하며 근무표를 재구성하는 기능을 구현했습니다.
- 철야조 소정근로시간과 하루 여러 건의 휴가를 반영하는 스케줄 생성 로직을 구현했습니다.
- 운영 중 발견된 결함 중 날짜별 일괄 변경 시 일부 날짜만 저장되던 문제(변경 전후 데이터를 짝짓는 키에 일자 누락), 짧은 활동이 화면에서 사라지던 문제(시간표 변환 로직의 덮어쓰기), 재등록 시 PK 중복 오류를 원인 확인 후 수정했습니다.

## 돌아보면

아래는 당시 구현한 내용이 아니라, 지금 다시 한다면 검토할 점입니다.

- **규칙을 테스트로 고정하기.** 경계가 맞닿는 경우, 시작시각이 같은 경우처럼 분기가 많은 로직이라, 처리 규칙을 단위 테스트로 먼저 고정해 두면 수정 후 확인이 빨라집니다.
- **변경분만 저장하기.** 변경 전후 근무표를 비교해 삭제할 구간과 추가할 구간만 뽑으면, DB 작업을 줄이고 이력도 명확해집니다.
- **동시 수정 대비.** 여러 관리자가 같은 사원의 근무표를 동시에 고치는 경우에 대한 제어는 없었습니다. 버전 값을 두고 저장 시 비교하는 방식(낙관적 락)을 검토할 수 있습니다.
